# Auto Apply supply ingestion

This is an internal service with no HTTP endpoint, scheduled job, or matching integration.

- `ingestSupply(observation)` takes a complete observation from a trusted server caller. Supply the same identity on recheck; omitted evidence and eligibility fields represent unknown current values. Only a trusted verification path should submit `VERIFIED`. An email additionally requires explicit confirmation that the inbox accepts training applications, documented evidence, and a non-generic destination.
- Email identity is normalized company and inbox plus a stable opportunity ID or normalized title. Omit both for an evergreen inbox with no specific opening. URL identity uses company and application URL, strips ordinary anchors and known marketing parameters, and retains meaningful query parameters and hash routes. Darbak applications prefer the Darbak opportunity ID and fall back to the application or source URL. A corrected identity (such as a changed destination) requires reviewer reconciliation; ingestion does not guess that two distinct identities are the same.
- The result reports `created`, `updated`, `duplicate`, `expired`, or `reactivated`. Rechecks can pass `lastCheckedAt`. Duplicate observations advance observation timestamps, while changed records retain the prior content and verification in their history. Changed content requires review unless verification is explicitly supplied. A Mongo unique index and version-checked updates prevent competing observations from creating a second row or silently losing history. Deployments with automatic index creation disabled must provision the declared indexes before ingestion.
- `findEligibleSupply({ limit, afterId })` reads a bounded page of verified, active records with neither an elapsed deadline nor an elapsed verification expiry. Eligibility here does not imply a match for any student or permission to send or submit an application.
- `legacyEmailObservation(channel, linkedOpportunity)` only converts supplied data. It does not read or write either legacy collection. An eventual import should iterate in bounded batches and explicitly call `ingestSupply` for each observation. No production import is included in this phase.
